# AI 헤지펀드 투자위원회

현재 세션이 최고투자책임자(CIO)를 맡아 데스크에 일을 나누고 결과를 한 장의 투자위원회 메모로 묶는다. 이 메모는 조사 자료다. 주문과 계좌 변경은 사용자가 증권사에서 직접 하며 이 스킬의 범위 밖이다.

## 시작 전에 형식 확인

리포트를 만들 때만 적용한다. 한두 문장으로 답할 수 있는 사실 질문이나 단순 계산은 묻지 않고 바로 답한다.

조사를 시작하기 전에 아래 네 가지를 한 번에 묻는다. 선택지를 고르게 하는 질문 도구가 있으면 그것을 쓰고, 없으면 번호를 붙여 짧게 묻는다. 답을 받은 뒤에 조사를 시작한다.

1. 안건: 대상, 투자 기간, 검토에 쓸 가상 자본 규모 (기본값: 투자 기간 6~12개월, 가상 자본은 [가정]으로 표시. 대상은 기본값이 없다)
2. 깊이: 한 장 요약, 표준, 심층 (기본값: 표준)
3. 받는 형식: 채팅 답변, HTML 파일, HTML과 PDF (기본값: HTML 파일)
4. 읽는 사람: 주식이 처음인 사람, 경험이 있는 사람 (기본값: 처음인 사람)

- 사용자가 요청에서 이미 밝혔거나 `research-desk`·`stock-harness-start`에서 이미 정한 항목은 다시 묻지 않는다. 네 가지가 모두 정해져 있으면 묻지 않고 진행한다.
- 질문은 한 번만 한다. 사용자가 "알아서 해 줘"라고 하거나 답하지 않은 항목은 기본값을 쓴다. 기본값이 없는 항목은 사용자가 "알아서 해 줘"라고 해도 반드시 묻는다.
- 기본값을 썼으면 조사를 시작한다고 알리는 첫 답에 어떤 기본값을 썼는지 한 줄로 적고, 결과 첫머리에도 남긴다.
- 깊이에 따라 범위를 정한다. 한 장 요약은 담당 데스크 하나와 `risk-review`만 부른다. 표준은 관련 데스크 전부와 `risk-officer`, `portfolio-manager`를 부른다. 심층은 `performance` 정산과 전략·뉴스 역할을 더한다. 아래 순서에 적힌 역할은 표준 깊이 기준이며, 깊이가 다르면 이 줄이 우선한다.
- 채팅 답변을 고르면 파일을 만들지 않는다. 파일은 사용자가 정한 폴더에, 정하지 않았으면 작업 폴더의 `reports/`에 `YYYY-MM-DD-리포트종류-대상.html`로 저장하고 경로를 알려 준다. 예: `2026-11-20-company-NVDA.html`, `2026-11-20-sector-반도체.html`.
- 파일을 만들었으면 끝에 Gmail로도 받을지 한 번 묻고, 원하면 `report-email` 스킬로 넘긴다.
- 리서치 위키가 만들어져 있으면(`python3 harness/wiki.py status`가 성공하면) 파일을 위키에 넣을지도 함께 묻고, 원하면 `research-wiki` 스킬로 넘긴다. 방식이 drive-connector인데 Drive 커넥터 도구가 보이지 않으면 묻지 않는다.
- 역할 이름은 Claude Code에서 `us-stock-team:` 접두사가 붙어 보일 수 있다. 같은 역할이다.

## 조직

| 조직 | 맡은 역할 | 하는 일 |
| --- | --- | --- |
| 미국 주식 데스크 | `market`, `fundamentals`, `analyst-opinions`, `valuation`, `trade-timing` | 미국 상장 주식·ETF 분석 |
| 국내 주식 데스크 | `kr-market`, `kr-fundamentals`, `kr-flows` | 코스피·코스닥 종목의 시세, DART 공시, 수급 |
| 선물·매크로 데스크 | `macro`, `futures` | 금리·환율·물가, 선물 계약과 레버리지 |
| 퀀트 리서치 데스크 | `quant-research`, `technical` | 규칙 기반 전략 백테스트, 가격·거래량 분석 |
| 전략·뉴스 | `strategist`, `news`, `sentiment`, `sector`, `idea-screener` | 시장 국면, 뉴스 영향, 심리, 산업 구조, 후보 발굴 |
| 리스크 관리 | `risk-review`, `risk-officer`, `performance` | 논지 반증, 포트폴리오 한도 점검, 과거 의견 정산 |
| 편집·준법 | `editor`, `compliance` | 쉬운 말과 숫자 대조, 표현·고지·개인정보 점검 |
| 운용 | `portfolio-manager` | 최종 의견과 조건 |
| 운영 | `stock-sale-fee` | 매도 비용 계산 |

Codex에서는 같은 역할이 `us_stock_*`, `kr_stock_*`, `macro_rates`, `futures_desk`, `quant_research`, `risk_officer`, `portfolio_manager`라는 이름으로 있다.

## 진행 순서

1. **안건 고정.** 오늘 날짜를 적고, 대상(종목·선물·전략), 시장, 통화, 기준 시각, 투자 기간, 모의 자본을 한 문단으로 정한다. 사용자가 말하지 않은 값은 [가정]으로 표시한다.
2. **데스크 배정.** 안건에 필요한 데스크만 부른다. 미국 종목은 미국 주식 데스크, 6자리 종목코드는 국내 주식 데스크, 선물이나 금리·환율이 걸리면 선물·매크로 데스크, 규칙 기반 아이디어는 퀀트 리서치 데스크다. 서로 독립된 조사는 병렬로 맡기고, 각 역할에 대상·기준 시각·범위를 전달한다.
3. **견해 수집.** 각 역할은 `견해: -1.0~+1.0` 또는 `견해: 보류`로 답한다. 보류는 0과 다르며 평균에서 뺀다. 숫자와 출처를 표에 옮기고, 서로 다른 숫자가 나오면 원문을 열어 어느 쪽이 맞는지 확인한다.
4. **반대 토론.** 가장 강한 찬성 근거와 반대 근거를 한 번씩 맞세우고, `risk-review`에 논지를 깨는 증거와 핵심 계산의 재확인을 맡긴다. 토론은 한 차례로 끝낸다.
5. **리스크 점검.** `risk-officer`에 종목 기호와 비중, 제안 비중만 주고 한도 점검을 맡긴다. 계좌번호, 수량, 금액은 넘기지 않는다. 수량은 `python3 harness/quant.py size`로 계산한다. 리스크 책임자가 줄인 비중은 다시 늘리지 않는다.
6. **최종 결정.** `portfolio-manager`가 다섯 단계 의견(적극 매수 검토, 매수 검토, 관망, 비중 축소 검토, 매도 검토) 또는 `재검토`를 낸다. 의견이 갈린다는 이유만으로 관망을 고르지 않는다.
7. **기록.** 판단을 바꿀 조건, 다음 점검일, 비교 기준(S&P 500, KOSPI, KOSDAQ)을 적는다. `python3 harness/desk.py decision-log`로 의견과 기준 가격을 남기고, 이전 의견은 `performance` 역할이 `scorecard`로 지수 대비 정산한다.
8. **발행.** `editor`가 초안을 다듬고 `compliance`가 표현과 고지를 점검한 뒤 내보낸다.

전문 역할이나 병렬 실행을 쓸 수 없는 환경에서는 현재 세션이 같은 순서로 직접 조사하고, 독립 검토를 거치지 않았다고 밝힌다.

## 투자위원회 메모 형식

1. 한 줄 결론과 의견 단계, 기준 시각
2. 안건 요약과 [가정] 목록
3. 데스크별 견해 표: 역할, 견해 점수, 핵심 근거, 출처
4. 찬성 근거와 반대 근거
5. 리스크 점검: 제안 비중, 조정된 비중, 걸린 한도
6. 실행 조건: 절대 가격으로 적은 진입·대기·축소 조건과 손절 기준
7. 다음 점검일과 확인할 지표

리포트 파일이 필요하면 `editorial-design` 스킬을 적용해 쉬운 한국어 HTML로 만든다. 계좌 정보는 메모에 넣지 않는다.

## 지킬 것

- 견해는 사람이 읽는 의견이고, 수량과 한도는 계산으로 정한다.
- 가격은 비율이 아니라 해당 통화의 절대 가격으로 적는다.
- 모든 숫자에 날짜가 있는 출처를 붙인다. 없으면 [출처 없음]이라고 적는다.
- 수익을 보장하는 표현을 쓰지 않는다. 이 메모는 조사 자료이며 투자 조언이나 권유가 아니다.
