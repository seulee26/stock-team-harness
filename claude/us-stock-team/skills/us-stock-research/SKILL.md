# 미국주식 리서치

종목·주식 클래스·통화를 확인하고, 사용자가 지정한 기준시각과 범위를 따른다. 시세는 USD와 미국 동부시간을 기본으로 한다. 현재 분석은 최신 검증 시세 또는 날짜가 확인되는 종가를 사용한다. 과거 날짜만 지정되면 해당일 23:59 ET까지 공개된 자료와 그 시점까지 완료된 마지막 정규장 종가를 사용한다. [출처와 날짜 기준](references/sources.md)을 적용한다.

## 시작 전에 형식 확인

리포트를 만들 때만 적용한다. 한두 문장으로 답할 수 있는 사실 질문이나 단순 계산은 묻지 않고 바로 답한다.

조사를 시작하기 전에 아래 네 가지를 한 번에 묻는다. 선택지를 고르게 하는 질문 도구가 있으면 그것을 쓰고, 없으면 번호를 붙여 짧게 묻는다. 답을 받은 뒤에 조사를 시작한다.

1. 관점: 새로 살지 검토, 보유 종목 점검, 실적 확인, 다른 종목과 비교 (기본값: 새로 살지 검토. 종목은 기본값이 없다)
2. 깊이: 한 장 요약, 표준, 심층 (기본값: 표준)
3. 받는 형식: 채팅 답변, HTML 파일, HTML과 PDF (기본값: HTML 파일)
4. 읽는 사람: 주식이 처음인 사람, 경험이 있는 사람 (기본값: 처음인 사람)

- 사용자가 요청에서 이미 밝혔거나 `research-desk`·`stock-harness-start`에서 이미 정한 항목은 다시 묻지 않는다. 네 가지가 모두 정해져 있으면 묻지 않고 진행한다.
- 질문은 한 번만 한다. 사용자가 "알아서 해 줘"라고 하거나 답하지 않은 항목은 기본값을 쓴다. 기본값이 없는 항목은 사용자가 "알아서 해 줘"라고 해도 반드시 묻는다.
- 기본값을 썼으면 조사를 시작한다고 알리는 첫 답에 어떤 기본값을 썼는지 한 줄로 적고, 결과 첫머리에도 남긴다.
- 깊이에 따라 범위를 정한다. 한 장 요약은 `fundamentals`와 `market`만 부르고 조건은 리드가 직접 쓴다. 표준은 의견, 가치평가, 매매 시점 역할을 더한다. 심층은 `risk-review`의 독립 검토까지 한다. 아래 순서에 적힌 역할은 표준 깊이 기준이며, 깊이가 다르면 이 줄이 우선한다.
- 채팅 답변을 고르면 파일을 만들지 않는다. 파일은 사용자가 정한 폴더에, 정하지 않았으면 작업 폴더의 `reports/`에 `YYYY-MM-DD-리포트종류-대상.html`로 저장하고 경로를 알려 준다. 예: `2026-11-20-company-NVDA.html`, `2026-11-20-sector-반도체.html`.
- 파일을 만들었으면 끝에 Gmail로도 받을지 한 번 묻고, 원하면 `report-email` 스킬로 넘긴다.
- 리서치 위키가 만들어져 있으면(`python3 harness/wiki.py status`가 성공하면) 파일을 위키에 넣을지도 함께 묻고, 원하면 `research-wiki` 스킬로 넘긴다. 방식이 drive-connector인데 Drive 커넥터 도구가 보이지 않으면 묻지 않는다.
- 역할 이름은 Claude Code에서 `us-stock-team:` 접두사가 붙어 보일 수 있다. 같은 역할이다.

## 조사와 검증

1. 플러그인 역할을 사용할 수 있으면 현재 세션이 리드를 맡는다. Claude Code에서 Agent Teams가 활성화되어 있으면 전문 역할을 팀원으로 지정하고, 일반 Agent 위임을 제공하는 세션에서는 같은 역할을 하위 에이전트로 실행한다. 위임 기능이나 역할을 사용할 수 있는지 먼저 확인하고, 기능이 없는 환경에서는 리드가 조사·계산·원문 대조를 수행한다. 팀 사용 여부는 실제 호출에 맞게 밝힌다.
2. `us-stock-team:fundamentals`에 공시·실적, `us-stock-team:market`에 시세·이벤트를 각각 맡긴다. 두 업무가 필요하면 병렬로 진행한다. 기준시각과 티커, 조사 범위, 참조 파일의 경로를 각 역할에 보내고 출처 링크가 담긴 결과를 기다린다. 시장 브리핑과 단일 지표에는 필요한 역할만 호출한다.
3. 개별 종목의 투자의견은 `us-stock-team:analyst-opinions`에 병렬 조사로 맡긴다. 가격과 실적이 확인된 뒤 `us-stock-team:trade-timing`에서 [단기 진입·축소 조건](references/timing.md)을 검토한다. 가치평가가 필요하면 `us-stock-team:valuation`에 입력값과 출처를 넘긴다. 심층 리서치는 `us-stock-team:risk-review`에 초안의 수치·산식·가격 조건을 넘겨 검증한다. 리드가 결과를 취합하고 완료된 팀원을 종료한다.
4. 사용자 제공 자료만 사용하라는 요청이면 모든 역할에 그 범위를 전달한다. 출처·날짜·거래 세션을 대조하고, 공시 수치와 회사 전망 및 분석 가정을 표시한다. 확인되지 않은 숫자나 일정은 공백으로 밝힌다. 주문, 계좌 변경, 외부 전송은 이 스킬의 범위 밖이다.

패키지 루트에서 `harness/stock_harness.py`를 실행할 수 있으면 `research-plan`의 기준시각과 단계 순서를 역할에 전달한다. 토스 시세는 `market-packet`의 공개 필드만 공유한다. 여섯 역할이 조사한 심층 리포트는 `research-check`로 자료의 공개 시각과 역할 누락을 확인한다. 계좌와 보유 자산은 공개 조사 범위에서 제외한다.

공개 시세·공시 또는 원본 금융 방법론이 필요하고 선택 통합을 설치한 경우에는 `stock-harness-integrations` 스킬로 OpenBB와 Anthropic Financial Services를 사용한다. 별도 TradingAgents 토론과 AI Hedge Fund 모의 체결은 요청받은 경우에 실행한다.

## 리포트

- [편집 디자인](references/editorial-design.md)을 적용해 문단, 줄바꿈, 글자 크기와 페이지 나눔을 검토한다. 모바일 HTML과 PDF는 각각 렌더링해 확인한다.
- 리드가 한국어 HTML 리포트를 만든다. 종목 분석에서는 지금 판단과 진입·대기·축소 조건을 먼저 설명하고, 외부 증권사 의견과 목표가를 단기 판단과 구분한다. 기업 실적의 핵심 변화와 위험, 실제 분석팀이 확인한 일을 짧게 덧붙인다. 주요 수치에 출처를 붙인다.
- [리포트 생성 안내](references/html-report.md)에 따라 번들된 렌더러로 만들고, PDF 요청에는 같은 내용을 PDF로 내보낸다. 스크립트와 자료는 이 `SKILL.md`의 폴더를 기준으로 찾는다. Claude Code의 기본 저장 위치는 작업 폴더의 `reports/`다. Claude 웹·Cowork에서는 사용자가 받을 수 있는 출력 폴더에 저장하고 파일 링크나 첨부를 전달한다.
- 수익을 보장하거나 사라·팔라고 지시하는 표현을 쓰지 않는다. "무조건 오르지", "그냥 사라고 해 줘" 같은 요청에는 보장할 수 없다고 답하고 근거와 조건을 담은 리포트를 제안한다. 리포트는 조사 자료이며 투자 조언이나 권유가 아니라고 적는다. 주문과 계좌 변경은 사용자가 증권사에서 직접 하며 이 스킬의 범위 밖이다.
