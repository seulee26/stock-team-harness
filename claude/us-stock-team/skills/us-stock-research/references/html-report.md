# HTML 리포트 제작

## 편집 원칙

- 제목 아래에 종목 또는 비교 대상, 기준일과 필요할 때 거래 세션을 적는다. 결론은 한 줄로 적고 이어지는 두세 문장에서 무엇이 바뀌었는지와 투자자가 왜 알아야 하는지를 설명한다.
- 핵심 숫자는 보통 세 개를 고른다. 금액은 통화를 명시하고 같은 금액 단위로 맞춘다. 증가율에는 비교 기준을 적는다. 예를 들어 `+18%`는 `전년 같은 분기보다 18% 증가`로 설명한다. P/E나 FCF는 처음 쓰이는 자리에서 뜻을 풀고 그 종목에서 숫자가 의미하는 바를 덧붙인다.
- 개별 종목은 실적, 주가에 반영된 기대, 다음에 볼 위험을 중심으로 구성한다. 종목 비교에는 공통 기준의 표 하나를, 실적 업데이트에는 실제치와 확인된 비교값을, 시장 브리핑에는 당일 변화와 다음 일정을 우선한다. 심층 수치와 가정은 사용자가 요청한 범위에 맞춘다. 데이터가 부족한 부분은 확인 가능한 사실과 공백을 적는다.
- 각 섹션에서 숫자나 사실의 출처를 연결한다. 회사 발표와 분석자의 해석은 문장과 소제목으로 구분한다. 용어 설명은 본문 이해에 필요한 한두 개로 충분하다. 과거 예시나 기준일 분석은 당시 정보라는 점을 상단에 밝힌다.

## 생성과 전달

아래 구조의 UTF-8 JSON을 임시 파일에 작성하고, 패키지 루트에서 `python3 harness/report.py render <입력.json> <결과.html>`로 렌더링한다(PDF도 받으려면 `--pdf`). 하네스 폴더가 없는 환경에서는 `python3 <스킬 폴더>/scripts/render_report.py <입력.json> <결과.html>`를 쓴다. 리포트 종류와 관계없이 모든 리포트를 이 방법으로 만들고 HTML을 직접 써서 만들지 않는다. `python3 harness/report.py check <결과.html>`로 표준 디자인인지 확인한다. 일반 저장 경로는 현재 작업 폴더의 `reports/`다. 사용자 지정 위치가 있으면 그 위치를 쓰고, 같은 경로를 덮어쓰라는 요청이 있으면 `--overwrite`를 붙인다. 채팅에 핵심 결론과 HTML 링크를 남긴다.

| 필드 | 입력 |
| --- | --- |
| `kind`, `title`, `as_of` | 리포트 종류, 기업·티커 또는 시장 이름, 데이터 기준일·시각. 필수 |
| `headline`, `summary` | 핵심 판단 한 줄과 짧은 설명. 설명은 문자열이나 문단 배열. 필수 |
| `summary_refs` | 핵심 판단의 근거가 되는 출처 번호 배열 |
| `metrics` | `label`, `value`, `note`, `refs`를 담은 배열. `note`는 기간, 단위 또는 의미를 설명한다 |
| `timing`, `timing_note` | 각 경우의 `label`, `trigger`, `action`, `refs`를 적는다. 현재 해당하는 판단을 첫 줄에 둔다. `action`과 `timing_note`는 문자열이나 문단 배열을 쓸 수 있다. 공통 기간과 장 마감 기준은 `timing_note`에 넣는다 |
| `sections` | 분석 섹션 배열. 각 섹션의 `title`과 `paragraphs`(문자열 배열)를 넣고, `refs`와 `table`을 선택해서 추가한다. `table`에는 `caption`, `columns`(문자열 배열), `rows`(문자열 배열의 배열)를 넣는다 |
| `watch` | 다음에 확인할 항목의 배열. 각 항목에 `label`, `text`, `refs`를 쓴다 |
| `terms` | 용어 풀이가 필요하면 `term`, `definition`을 담은 배열을 추가한다 |
| `team` | 실제 리서치에 참여한 역할과 확인 결과를 `role`, `contribution`으로 적는다 |
| `sources` | 출처의 `label`, `url`을 담은 배열. 문서 안의 `refs`는 이 배열에서 1부터 센 번호다 |

값과 문단에는 일반 텍스트를 쓴다. 링크는 `sources`에 넣는다. 비어 있는 선택 항목은 생략할 수 있다. 렌더링 후 기준일, 핵심 수치, 인용 번호와 링크를 대조하고 표가 모바일에서도 읽히는지 확인한다. 스크립트 실행이 어려우면 [HTML 레이아웃](../assets/report.html)을 직접 채워 동일한 구조로 전달한다.

## PDF

`python3 <스킬 폴더>/scripts/render_pdf.py <결과.html> <결과.pdf>`로 원문을 A4 PDF로 인쇄한다. Chrome이나 Chromium을 찾지 못하면 `--browser <실행 파일>`을 주거나 브라우저의 PDF 저장 기능을 사용한다. 생성한 PDF의 페이지 수, 한글 글꼴, 잘린 표나 문단, 출처 링크를 확인하고 HTML과 동일한 분석 내용을 전달한다.

## Google Drive 보관

프로젝트 지침에 지정된 Drive 보관 폴더 아래에서 `YYYY-MM-DD` 형식의 리포트 기준일 폴더를 찾고, 없으면 만든다. HTML과 PDF를 각각 `회사명 (티커) - YYYY-MM-DD.html`, `회사명 (티커) - YYYY-MM-DD.pdf`로 올린다. 같은 이름이 이미 있으면 파일을 먼저 확인한다. 해당 리포트의 수정본이면 기존 Drive 파일에 새 버전을 올려 링크를 유지한다.

업로드 후 날짜 폴더에서 두 파일의 이름과 형식, 링크를 확인한다. 답변에는 모바일용 PDF 링크와 날짜 폴더 링크를 넣는다. Drive 연결을 사용할 수 없으면 생성한 파일을 전달하고 Drive에 저장하지 못한 이유를 밝힌다.
