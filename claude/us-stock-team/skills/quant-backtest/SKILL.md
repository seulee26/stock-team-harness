# 퀀트 백테스트

전략 아이디어를 규칙으로 바꾸고 과거 일봉으로 검증한다. 패키지 루트의 `harness/quant.py`는 파이썬 기본 기능만 쓰며 주문을 보내지 않는다.

## 시작 전에 형식 확인

리포트를 만들 때만 적용한다. 한두 문장으로 답할 수 있는 사실 질문이나 단순 계산은 묻지 않고 바로 답한다.

조사를 시작하기 전에 아래 네 가지를 한 번에 묻는다. 선택지를 고르게 하는 질문 도구가 있으면 그것을 쓰고, 없으면 번호를 붙여 짧게 묻는다. 답을 받은 뒤에 조사를 시작한다.

1. 데이터와 전략: 가진 일봉 파일이 있는지, 어떤 전략과 기간을 볼지 (기본값: 파일이 없으면 합성 데이터 시연, 전략은 20일·60일 이동평균 교차)
2. 깊이: 한 장 요약, 표준, 심층 (기본값: 표준)
3. 받는 형식: 채팅 답변, HTML 파일, HTML과 PDF (기본값: 채팅 답변)
4. 읽는 사람: 주식이 처음인 사람, 경험이 있는 사람 (기본값: 처음인 사람)

- 사용자가 요청에서 이미 밝혔거나 `research-desk`·`stock-harness-start`에서 이미 정한 항목은 다시 묻지 않는다. 네 가지가 모두 정해져 있으면 묻지 않고 진행한다.
- 질문은 한 번만 한다. 사용자가 "알아서 해 줘"라고 하거나 답하지 않은 항목은 기본값을 쓴다.
- 기본값을 썼으면 조사를 시작한다고 알리는 첫 답에 어떤 기본값을 썼는지 한 줄로 적고, 결과 첫머리에도 남긴다.
- 깊이에 따라 범위를 정한다. 한 장 요약은 한 번 실행한 결과만 보여 준다. 표준은 비용 두 배(`--cost-bps 10`)와 파라미터 두 조합을 더 돌린다. 골든크로스면 그 두 조합 중 하나가 50일·200일이다. `demo`도 `backtest`와 같은 옵션(`--strategy`, `--fast`, `--slow`, `--lookback`, `--cost-bps`)을 받는다. 심층은 `quant-research` 역할의 과최적화 점검까지 한다. 아래 순서에 적힌 역할은 표준 깊이 기준이며, 깊이가 다르면 이 줄이 우선한다.
- 채팅 답변을 고르면 파일을 만들지 않는다. 파일은 사용자가 정한 폴더에, 정하지 않았으면 작업 폴더의 `reports/`에 `YYYY-MM-DD-리포트종류-대상.html`로 저장하고 경로를 알려 준다. 예: `2026-11-20-company-NVDA.html`, `2026-11-20-sector-반도체.html`.
- 파일을 만들었으면 끝에 Gmail로도 받을지 한 번 묻고, 원하면 `report-email` 스킬로 넘긴다.
- 리서치 위키가 만들어져 있으면(`python3 harness/wiki.py status`가 성공하면) 파일을 위키에 넣을지도 함께 묻고, 원하면 `research-wiki` 스킬로 넘긴다. 방식이 drive-connector인데 Drive 커넥터 도구가 보이지 않으면 묻지 않는다.
- 역할 이름은 Claude Code에서 `us-stock-team:` 접두사가 붙어 보일 수 있다. 같은 역할이다.

## 진행 순서

1. **규칙을 글로 고정.** 대상, 기간, 진입·청산 조건, 비용 가정을 실행 전에 적는다. 결과를 보고 규칙을 바꾸면 바꿨다고 기록한다.
2. **데이터 준비.** `date,close` 열이 있는 CSV가 필요하다. 사용자가 가진 파일을 쓰거나, 선택 통합이 설치돼 있으면 `python3 harness/integrations.py price TICKER --start ... --end ...` 결과를 CSV로 바꿔 쓴다. 데이터가 없으면 `python3 harness/quant.py demo`로 계산 방식만 시연하고 합성 데이터라고 밝힌다.
3. **실행.**

| 목적 | 명령 |
| --- | --- |
| 이동평균 교차 (골든크로스) | `python3 harness/quant.py backtest bars.csv --strategy sma-cross --fast 20 --slow 60` |
| 추세 모멘텀 | `python3 harness/quant.py backtest bars.csv --strategy momentum --lookback 120` |
| 고점·저점 돌파 | `python3 harness/quant.py backtest bars.csv --strategy breakout --lookback 55 --allow-short` |
| 단순 보유 비교 | `python3 harness/quant.py backtest bars.csv --strategy buy-hold` |
| 선물 방식 | 위 명령에 `--capital 50000 --multiplier 50 --fee 2.5 --margin 15000` 추가 |
| 수량 계산 | `python3 harness/quant.py size --capital 10000 --risk-pct 1 --entry 100 --stop 95` |

4. **점검.** `quant-research` 역할에 아래를 맡기거나 직접 확인한다.
   - 신호가 생긴 날의 수익을 가져가지 않았는가. 하네스는 종가 신호를 다음 봉 수익에만 적용한다.
   - 비용(`--cost-bps`)을 두 배로 올려도 결과가 남는가.
   - 파라미터를 조금 바꿔도 비슷한가. 시험한 조합 수를 적는다.
   - 기간에 큰 하락장이 들어 있는가. 표본이 1년 미만이면 결론을 내리지 않는다.
   - 수정주가인가. 상장폐지 종목이 빠진 자료는 아닌가.
5. **보고.** 총수익률, 연환산 수익률, 최대 낙폭, 변동성, 샤프 지수, 포지션 변경 횟수를 단순 보유와 나란히 표로 보여 준다. 단순 보유 값은 같은 출력의 `buyAndHold`에 있으며 비용을 빼지 않은 값이다. 출력의 `warnings`를 그대로 옮긴다.
6. **골든크로스.** 사용자가 기간을 말하지 않으면 20일·60일로 돌리고, 흔히 쓰는 50일·200일도 함께 돌려 결과가 기간에 따라 달라지는지 보여 준다.

Codex에서는 `quant_research` 역할을 쓴다.

## 더 정교한 도구

`python3 harness/connectors.py catalog`에 검토한 오픈소스 목록과 라이선스, 주문 기능 여부가 있다. 연속 선물과 만기 교체를 제대로 다루려면 Lean이나 backtrader를, 팩터·머신러닝 연구에는 qlib을 사용자가 직접 설치해 쓰도록 안내한다. GPL·AGPL·Commons Clause 라이선스 도구는 패키지에 넣지 않는다. 주문 기능이 있는 도구는 백테스트 모드로만 쓰고 증권사·거래소 키를 연결하지 않는다.

## 지킬 것

- 백테스트는 과거 기록이다. 미래 수익을 보장한다고 쓰지 않는다.
- 가장 좋은 결과 하나만 보여 주지 않는다. 나쁜 구간도 함께 보여 준다.
- 실거래 자동매매 코드는 만들지 않는다.
