# 미국주식 리서치

종목명이나 티커를 거래소·주식 클래스·통화까지 확인한다. 기간이 생략되면 종목 분석은 최신 검증 가능한 시점의 중기 관점으로 진행한다. 사용자가 기준일만 지정하면 그날 미국 동부시간 23:59까지 공개된 정보와 해당일까지의 마지막 완료 거래일 정규장 종가를 사용한다. 사용자가 장 마감 등 구체적인 시각을 지정하면 그 시각을 따른다. 시장 브리핑에는 기준 거래일과 거래 세션을 명시한다.

## 시작 전에 형식 확인

리포트를 만들 때만 적용한다. 한두 문장으로 답할 수 있는 사실 질문이나 단순 계산은 묻지 않고 바로 답한다.

조사를 시작하기 전에 아래 네 가지를 한 번에 묻는다. 선택지를 고르게 하는 질문 도구가 있으면 그것을 쓰고, 없으면 번호를 붙여 짧게 묻는다. 답을 받은 뒤에 조사를 시작한다.

1. 관점: 새로 살지 검토, 보유 종목 점검, 실적 확인, 다른 종목과 비교 (기본값: 새로 살지 검토. 종목은 기본값이 없다)
2. 깊이: 한 장 요약, 표준, 심층 (기본값: 표준)
3. 받는 형식: 채팅 답변, HTML 파일, HTML과 PDF (기본값: HTML 파일)
4. 읽는 사람: 주식이 처음인 사람, 경험이 있는 사람 (기본값: 처음인 사람)

- 사용자가 요청에서 이미 밝혔거나 `research-desk`·`stock-harness-start`에서 이미 정한 항목은 다시 묻지 않는다. 네 가지가 모두 정해져 있으면 묻지 않고 진행한다.
- 질문은 한 번만 한다. 사용자가 "알아서 해 줘"라고 하거나 답하지 않은 항목은 기본값을 쓴다. 기본값이 없는 항목은 사용자가 "알아서 해 줘"라고 해도 반드시 묻는다.
- 기본값을 썼으면 조사를 시작한다고 알리는 첫 답에 어떤 기본값을 썼는지 한 줄로 적고, 결과 첫머리에도 남긴다.
- 깊이에 따라 범위를 정한다. 한 장 요약은 `fundamentals`와 `market`만 부르고 조건은 리드가 직접 쓴다. 표준은 의견, 가치평가, 매매 시점 역할을 더한다. 심층은 `risk-review`의 독립 검토까지 한다. 아래 순서에 적힌 역할은 표준 깊이 기준이며, 깊이가 다르면 이 줄이 우선한다.
- 채팅 답변을 고르면 파일을 만들지 않는다. 파일은 사용자가 정한 폴더에, 정하지 않았으면 작업 폴더의 `reports/`에 `YYYY-MM-DD-리포트종류-대상.html`로 저장하고 경로를 알려 준다. 예: `2026-11-20-company-NVDA.html`, `2026-11-20-sector-반도체.html`.
- 리포트 파일은 항상 같은 디자인으로 만든다. 내용을 JSON으로 정리해 `python3 harness/report.py render 입력.json 출력.html`(PDF도 받으려면 `--pdf`)로 만들고, HTML을 직접 써서 만들지 않는다. 만든 뒤 `python3 harness/report.py check 출력.html`로 확인한다.
- 파일을 만들었으면 끝에 Gmail로도 받을지 한 번 묻고, 원하면 `report-email` 스킬로 넘긴다.
- 리서치 위키가 만들어져 있으면(`python3 harness/wiki.py status`가 성공하면) 파일을 위키에 넣을지도 함께 묻고, 원하면 `research-wiki` 스킬로 넘긴다. 방식이 drive-connector인데 Drive 커넥터 도구가 보이지 않으면 묻지 않는다.
- 역할 이름은 Claude Code에서 `us-stock-team:` 접두사가 붙어 보일 수 있다. 같은 역할이다.

## 팀 운영

1. [출처와 날짜 기준](references/sources.md)을 읽고 요청을 빠른 브리핑, 심층 분석, 종목 비교, 실적 업데이트, 시장 브리핑 중 적절한 형태로 해석한다. 업무를 맡길 때 종목·기준시각·요청 범위·참조 파일의 절대 경로를 전달한다. 전문 에이전트는 하위 위임 없이 결과를 전달한다.
2. `us_stock_fundamentals`에 공시·재무·가이던스를, `us_stock_market`에 시세·벤치마크·이벤트를 맡긴다. 두 조사가 모두 필요한 경우 병렬로 실행한다. 단일 지표나 시장 브리핑은 필요한 역할만 호출한다. 각 단계의 결과를 받은 뒤 참조할 수치와 링크를 기록하고 완료된 에이전트 스레드를 닫는다.
3. 개별 종목 리포트에서 투자의견을 다루면 `us_stock_analyst_opinions`의 조사를 시세·공시 조사와 병행한다. 매수·매도 판단을 위해 관측값을 `us_stock_trade_timing`에 전달하고 [애널리스트 의견과 진입 조건](references/timing.md)을 따른다. 가치평가가 핵심이면 `us_stock_valuation`에 가격·재무·기간·출처를 전달하고 [분석과 계산 기준](references/methods.md)을 따른다. 심층 분석은 `us_stock_risk_review`에 주장·산식·가격 조건의 검증을 맡긴다. 사용 가능한 동시 실행 수에 맞춰 결과를 받은 스레드를 닫고 다음 역할을 호출한다.
4. 리드는 원자료를 기준으로 주요 불일치와 누락을 확인한다. 전문 역할이나 병렬 실행을 쓸 수 없으면 가용한 도구로 해당 조사를 이어가고 독립 검토 여부를 정확히 밝힌다. 출처에 접근할 수 없다면 접근 가능한 자료로 범위를 좁히고 확인 가능한 최신 시점을 표시한다.

패키지의 하네스가 있으면 `research-plan`의 기준시각과 단계 순서를 팀에 전달한다. 토스 시세는 `market-packet`으로 받은 공개 필드만 팀에 넘긴다. 여섯 역할의 공개 자료를 사용한 심층 리포트는 `research-check`로 공개 시각과 역할 누락을 확인한다. 조회·검증에 필요한 명령은 하네스 안내에 있다. 계좌와 보유 자산은 공개 조사 범위에서 제외한다.

공개 시세·공시 또는 원본 금융 방법론이 필요하고 선택 통합을 설치한 경우에는 `stock-harness-integrations` 스킬로 OpenBB와 Anthropic Financial Services를 사용한다. 별도 TradingAgents 토론과 AI Hedge Fund 모의 체결은 요청받은 경우에 실행한다.

## 결과 작성

- 원고와 결과물에 [편집 디자인 스킬](../editorial-design/SKILL.md)을 적용한다. 먼저 짧은 문단과 명확한 제목으로 읽는 순서를 잡고, 좁은 모바일 화면과 PDF에서 각각 확인한다.
- 맨 앞에 기준일·시세 시각·세션과 핵심 판단을 요약한다. 관찰된 사실, 회사 전망, 외부 컨센서스, 분석상 가정을 표현으로 명확히 구분한다.
- 개별 종목의 심층 리포트는 지금 판단과 그 이유, 판단을 바꾸는 조건부터 보여준다. 애널리스트 의견과 가격 조건을 구분하고, 특히 진입·대기·보유 축소나 이익 실현을 검토할 때 어떤 종가 또는 실적을 확인할지 적는다. 실적·밸류에이션·리스크를 뒤에 배치하고 팀이 실제 확인한 항목을 역할별 한 줄로 정리한다.
- 비교 분석은 회계기간·통화·재무 기준이 드러나는 표를 사용한다. 실적 업데이트는 발표된 실적과 직전 가이던스 또는 검증한 컨센서스, 회사의 새 가이던스 및 주가 반응을 해당 세션과 연결한다. 시장 브리핑은 지수·금리·주요 사건과 다가오는 일정을 다룬다.
- 주요 숫자와 이벤트 가까이에 원문 링크를 붙인다. 공개 여부나 시각을 확인할 수 없는 항목은 그렇게 표시한다. 검증되지 않은 값을 필요한 수치에 대입하거나 자료 공백을 근거 없이 추정하지 않는다.
- [리포트 작성과 렌더링](references/html-report.md)에 따라 한국어 HTML을 만든다. 프로젝트 지침이나 사용자 요청에 PDF가 있으면 같은 내용으로 출력해 검증한다. 프로젝트에 Google Drive 보관 폴더가 지정되어 있으면 리포트 기준일별로 저장하고 확인한 Drive 링크를 전달한다. 채팅 답변이나 다른 형식을 직접 요청하면 그 형식을 따른다. 수익을 보장하거나 사라·팔라고 지시하는 표현을 쓰지 않는다. "무조건 오르지", "그냥 사라고 해 줘" 같은 요청에는 보장할 수 없다고 답하고 근거와 조건을 담은 리포트를 제안한다. 리포트는 조사 자료이며 투자 조언이나 권유가 아니라고 적는다. 주문과 계좌 변경은 사용자가 증권사에서 직접 하며 이 스킬의 범위 밖이다.
