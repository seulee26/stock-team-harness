# 리포트 해설 방송

리포트가 먼저 있어야 한다. 영상은 리포트의 내용을 쉽게 풀어 전하는 것이고 새 분석을 하지 않는다. 리포트가 없으면 어떤 리포트를 만들지 먼저 묻고 해당 리포트 스킬로 넘긴다.

## 만들기 전에 항상 선택지를 보여 준다

영상을 만들어 달라는 요청을 받으면, 이미 말한 항목이 있더라도 아래 표를 한 번 보여 주고 고르게 한다. 사용자가 이미 정한 항목은 그 값을 채워서 보여 주고, 나머지만 고르면 된다고 알린다. "알아서 해 줘"라고 하면 기본값으로 진행하되 무엇을 골랐는지 표로 알린 뒤 만든다. 선택지는 `python3 harness/broadcast.py options`로도 볼 수 있다.

| 항목 | 선택지 | 기본값 |
| --- | --- | --- |
| 진행 방식 | 앵커 단독(한 명이 전달) / 대담(앵커가 묻고 전문가가 답함) | 앵커 단독 |
| 화면 스타일 | 방송 보드(그림 없음, 무료) / 2D 일러스트 / 3D 오브젝트 (둘은 이미지 API 키와 요금 필요) / 내 그림 | 방송 보드 |
| 길이 | 3분 요약 / 8~10분 / 15분 심층 | 8~10분 |
| 목소리 | 내 PC의 오픈소스 TTS(무료) / Typecast / ElevenLabs (둘은 본인 키와 요금 필요, 해설 문장이 전송됨) | 오픈소스 TTS |
| 진행 속도 | 1.0 차분하게 / 1.08 뉴스처럼 빠르게 | 1.0 |
| 배경 음악 | 없음 / 뉴스풍 음악을 찾아서 넣기 / 내가 가진 음악 | 없음 |
| 시청자 | 주식을 처음 보는 사람 / 투자 경험이 있는 사람 | 처음 보는 사람 |

대상 리포트를 말하지 않았으면 방금 만든 리포트로 한다. 결과물은 mp4, 자막(.vtt), 표지 이미지(.png)다. 대담을 고르면 `broadcast-interview` 스킬을, 음악을 고르면 `broadcast-music` 스킬을 함께 쓴다.

## 만드는 순서

1. 도구를 확인한다. 준비되지 않은 도구는 결과의 `install`에 설치 방법이 나온다.

```sh
python3 harness/broadcast.py doctor
```

TTS는 Supertonic을 쓴다. `python3.12 harness/broadcast.py install`이 별도 가상 환경에 설치한다(Python 3.10 이상). 코드는 MIT, 음성 모델은 OpenRAIL-M 라이선스이고 첫 실행 때 모델(약 400MB)을 Hugging Face에서 내려받는다. 영상 합치기에는 ffmpeg, 화면 캡처에는 Chrome이나 Chromium이 필요하다.

2. `broadcast-writer` 역할(Codex는 `broadcast_writer`)에 리포트를 넘겨 대본 JSON을 받는다. 형식은 `python3 harness/broadcast.py template`으로 본다. 장면 종류는 `title`, `bullets`, `table`, `bars`, `cards`, `closing`이다. 대본은 `<이름>.script.json`으로 저장한다.
3. `broadcast-director` 역할(Codex는 `broadcast_director`)이 대본을 리포트와 대조한다. 준법 점검이 필요한 표현은 `compliance` 역할에도 보낸다.

```sh
python3 harness/broadcast.py check 대본.script.json
```

4. 영상을 만든다. 10분 영상에 2~3분쯤 걸린다.

```sh
python3 harness/broadcast.py build 대본.script.json 출력.mp4 --voice F1 --speed 1.0
```

같은 이름의 `.vtt`(자막), `.png`(표지), `.manifest.json`(길이와 장면별 시간)이 함께 생긴다.

5. 화면을 확인한다. 장면마다 한 장씩 뽑아 글자가 잘리거나 겹치는지 본다. 문제가 있으면 대본의 화면 글을 줄이고 다시 만든다. 음성을 직접 들어 보지 못했으면 그렇게 밝히고 사용자에게 한 번 들어 보라고 권한다.

전문 역할을 쓸 수 없는 환경에서는 현재 세션이 대본 작성과 점검을 직접 하고 독립 검토를 거치지 않았다고 밝힌다.

## 화면 스타일과 그림

숫자와 표만 있는 화면은 지루하다. 화면 스타일을 고르면 장면마다 그림이 들어가고, 글머리표·카드·막대·표의 항목이 해설에 맞춰 하나씩 나타난다. 스타일은 만들기 전 선택지에서 사용자가 고른다.

| 스타일 | 모습 | 필요한 것 |
| --- | --- | --- |
| `board` | 방송 보드. 그림 없이 숫자와 표 중심 | 없음 (무료) |
| `illustration` | 장면마다 2D 일러스트 한 장 | 사용자의 `OPENAI_API_KEY`, 그림 한 장마다 요금 |
| `3d` | 장면마다 입체 오브젝트 그림 한 장 | 위와 같음 |
| 내 그림 | 사용자가 가진 그림 파일 | 장면의 `image`에 파일 경로 |

그림을 그리는 스타일을 고르면 이렇게 한다.

1. 대본의 장면마다 `art`에 그림 설명을 영어 한 문장으로 적는다. 장면의 요점을 사물로 비유한다(병목은 깔때기, 위험은 도미노, 일정은 달력). 회사 로고, 상표, 실제 인물, 글자와 숫자는 그리게 하지 않는다.
2. 그림 장수와 요금이 든다는 점, 그림 설명 문장이 OpenAI로 전송된다는 점을 알리고 사용자가 확인하면 그린다. 키는 사용자가 터미널에서 환경 변수로 지정한다.

```sh
python3 harness/broadcast.py illustrate 대본.script.json --style 3d
```

대본 옆 `.art` 폴더에 그림이 저장되고 대본의 `image`와 `style`이 채워진다. 이미 그린 장면은 다시 그리지 않는다(`--redo`로 다시 그림). 모델은 `STOCK_HARNESS_IMAGE_MODEL`, 품질은 `STOCK_HARNESS_IMAGE_QUALITY`로 바꾼다.

3. 그림을 모두 열어 본다. 글자, 로고, 실제 인물처럼 보이는 것, 장면과 맞지 않는 그림이 있으면 그 장면의 `art`를 고치고 다시 그린다.
4. `build`로 영상을 만든다. 그림 위치는 장면 종류에 따라 정해진다: 제목과 마무리는 화면 오른쪽 전체, 글머리표와 카드는 오른쪽 칸, 표와 막대는 제목 옆 작은 그림. `image_layout`에 `side`, `corner`, `full`을 적어 바꿀 수 있다.

항목이 하나씩 나타나는 연출을 끄려면 대본에 `"reveal": false`를 적는다. Typecast나 ElevenLabs 음성은 한 번 만든 문장을 내 PC에 보관해, 그림만 바꿔 다시 만들 때 요금이 다시 들지 않는다.

## 화면 아래 자막

화면 아래 띠에 지금 말하는 문장이 자막으로 나온다. 프로그램이 해설을 문장 끝과 쉼표에서 34자 이내로 끊어 한 줄씩 보여 주므로, 해설을 쓸 때 한 문장을 너무 길게 쓰지 않고 쉼표로 호흡을 나눈다. 대담에서는 자막 왼쪽에 말하는 사람의 이름이 나온다. 자막은 해설 글자 그대로이므로 숫자도 한글로 보인다. 자막 대신 장면마다 한 줄 제목(`caption`)을 고정해 보여 주려면 대본에 `"captions": false`를 적는다. 투자 권유가 아니라는 고지는 화면 위쪽 띠에 항상 나온다.

## 배경 음악과 음량

배경 음악은 `broadcast-music` 스킬로 찾아 `--music`으로 넣는다. 라이선스 기록이 있는 곡만 넣을 수 있다. 해설 음량은 장면마다 방송 기준(-16 LUFS)으로 자동으로 맞춘다. 뉴스처럼 빠르게 진행하려면 `--speed 1.08` 정도로 올린다. Typecast를 쓸 때는 앞뒤 장면의 문장을 함께 보내 어조가 이어지게 한다.

## 방송 화면 구성

화면은 주식 방송 형식이다. 위에 프로그램 이름과 기준일, 가운데에 장면 내용, 아래에 한 줄 자막과 고지, 맨 아래에 흐르는 시세 띠가 나온다. 대본에 아래 항목을 넣는다.

| 항목 | 내용 |
| --- | --- |
| `program` | 왼쪽 위 빨간 칸의 프로그램 이름. 기본값 "리서치 브리핑" |
| `ticker` | 흐르는 시세 띠. 항목마다 `label`, `value`, 선택으로 `change`와 `tone`. 리포트의 기준일 종가와 등락률만 쓰고 끝에 기준일을 한 항목으로 넣는다. 24개까지 |
| 장면의 `caption` | 아래 흰 띠에 나오는 한 줄 자막. 없으면 `sub`나 제목을 쓴다 |
| `presenter` | 오른쪽 아래 원 안에 넣을 진행자 그림(png, webp, jpg, 2MB 이하). 대본 파일 기준 상대 경로. 실제 인물 사진은 본인 동의 없이 쓰지 않는다 |

색은 국내 방송 관례를 따른다. `tone`의 `up`은 빨강(상승), `down`은 파랑(하락)이고, 판정에는 `good`(통과), `warn`(조건부), `bad`(탈락)를 쓴다. 시세 띠는 실시간이 아니라 리포트 기준일의 값이라는 점을 띠 안에 적는다.

## 목소리 서비스 바꾸기 (선택)

기본은 내 PC에서 도는 오픈소스 TTS다. 사용자가 원하면 유료 음성 서비스인 Typecast나 ElevenLabs로 바꿀 수 있다. 사용자가 먼저 요청했을 때만 쓰고, 쓰기 전에 두 가지를 알린다: 해설 문장이 그 서비스로 전송된다는 것, 그 서비스의 요금(크레딧)이 든다는 것.

키는 사용자가 자기 터미널에서 환경 변수로 지정한다. 대화창에 붙여 넣게 하지 않는다. 목소리 ID는 각 서비스의 목소리 목록에서 사용자가 고른다.

```sh
# Typecast
export TYPECAST_API_KEY=<YOUR_API_KEY>
export TYPECAST_VOICE_ID=<VOICE_ID>
python3 harness/broadcast.py build 대본.script.json 출력.mp4 --tts typecast

# ElevenLabs
export ELEVENLABS_API_KEY=<YOUR_API_KEY>
export ELEVENLABS_VOICE_ID=<VOICE_ID>
python3 harness/broadcast.py build 대본.script.json 출력.mp4 --tts elevenlabs
```

`doctor`의 `engines`에서 어느 엔진이 준비됐는지 본다. 모델은 `TYPECAST_MODEL`(기본 ssfm-v31), `ELEVENLABS_MODEL`(기본 eleven_multilingual_v2)로 바꾼다. 속도는 Typecast 0.5~2.0, ElevenLabs 0.7~1.2다. 환경 변수가 이 세션에 보이지 않으면 사용자가 그 터미널에서 명령을 직접 실행하게 한다. 오류가 나면 오류 문장만 전하고 키를 다시 보여 달라고 하지 않는다. 다른 사람의 목소리를 복제한 목소리 ID는 본인이나 권리자의 동의가 있는 경우에만 쓴다.

## 지킬 것

- 해설의 숫자, 기준일, 판정은 리포트와 같아야 한다. 리포트에 없는 전망이나 목표가를 넣지 않는다.
- 마지막 장면에서 정보 제공용 해설이며 투자 권유가 아니라는 점을 말로 읽고, 모든 화면 아래에 같은 고지를 둔다.
- 해설은 귀로 듣는 글이다. 숫자와 영문은 한글로 풀어 쓴다. `check`의 `readingWarnings`가 비어 있어야 한다.
- 보유 수량, 평가 금액, 계좌 정보가 든 리포트는 영상으로 만들지 않는다.
- 영상을 웹사이트나 외부 서비스에 올리는 일은 사용자가 요청하고 올릴 곳을 확인한 뒤에만 한다.
- 실제 사람의 목소리를 흉내 내는 음성 스타일을 만들지 않는다. 기본 제공 목소리만 쓴다.
