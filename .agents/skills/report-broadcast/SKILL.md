# 리포트 해설 방송

리포트가 먼저 있어야 한다. 영상은 리포트의 내용을 쉽게 풀어 전하는 것이고 새 분석을 하지 않는다. 리포트가 없으면 어떤 리포트를 만들지 먼저 묻고 해당 리포트 스킬로 넘긴다.

## 시작 전에 형식 확인

이미 밝힌 항목은 묻지 않는다. "알아서 해 줘"에는 기본값을 쓴다.

| 항목 | 기본값 |
| --- | --- |
| 대상 리포트 | 방금 만든 리포트 |
| 길이 | 8~10분 (장면 12~15개) |
| 시청자 | 주식을 처음 보는 사람 |
| 목소리 | F1 (여성). F1~F5, M1~M5 중 선택 |
| 받는 형식 | mp4, 자막(.vtt), 표지 이미지(.png) |

## 만드는 순서

1. 도구를 확인한다. 준비되지 않은 도구는 결과의 `install`에 설치 방법이 나온다.

```sh
python3 harness/broadcast.py doctor
```

TTS는 Supertonic을 쓴다. `python3.12 harness/broadcast.py install`이 별도 가상 환경에 설치한다(Python 3.10 이상). 코드는 MIT, 음성 모델은 OpenRAIL-M 라이선스이고 첫 실행 때 모델(약 400MB)을 Hugging Face에서 내려받는다. 영상 합치기에는 ffmpeg, 화면 캡처에는 Chrome이나 Chromium이 필요하다.

2. `broadcast-writer` 역할(Codex는 `broadcast_writer`)에 리포트를 넘겨 대본 JSON을 받는다. 형식은 `python3 harness/broadcast.py template`으로 본다. 장면 종류는 `title`, `bullets`, `table`, `bars`, `cards`, `closing`이다. 대본은 `<이름>.script.json`으로 저장한다.
3. `broadcast-director` 역할(Codex는 `broadcast_director`)이 대본을 리포트와 대조한다. 준법 점검이 필요한 표현은 `compliance` 역할에도 보낸다.

```sh
python3 harness/broadcast.py check 대본.script.json
```

4. 영상을 만든다. 10분 영상에 2~3분쯤 걸린다.

```sh
python3 harness/broadcast.py build 대본.script.json 출력.mp4 --voice F1 --speed 1.0
```

같은 이름의 `.vtt`(자막), `.png`(표지), `.manifest.json`(길이와 장면별 시간)이 함께 생긴다.

5. 화면을 확인한다. 장면마다 한 장씩 뽑아 글자가 잘리거나 겹치는지 본다. 문제가 있으면 대본의 화면 글을 줄이고 다시 만든다. 음성을 직접 들어 보지 못했으면 그렇게 밝히고 사용자에게 한 번 들어 보라고 권한다.

전문 역할을 쓸 수 없는 환경에서는 현재 세션이 대본 작성과 점검을 직접 하고 독립 검토를 거치지 않았다고 밝힌다.

## 지킬 것

- 해설의 숫자, 기준일, 판정은 리포트와 같아야 한다. 리포트에 없는 전망이나 목표가를 넣지 않는다.
- 마지막 장면에서 정보 제공용 해설이며 투자 권유가 아니라는 점을 말로 읽고, 모든 화면 아래에 같은 고지를 둔다.
- 해설은 귀로 듣는 글이다. 숫자와 영문은 한글로 풀어 쓴다. `check`의 `readingWarnings`가 비어 있어야 한다.
- 보유 수량, 평가 금액, 계좌 정보가 든 리포트는 영상으로 만들지 않는다.
- 영상을 웹사이트나 외부 서비스에 올리는 일은 사용자가 요청하고 올릴 곳을 확인한 뒤에만 한다.
- 실제 사람의 목소리를 흉내 내는 음성 스타일을 만들지 않는다. 기본 제공 목소리만 쓴다.
