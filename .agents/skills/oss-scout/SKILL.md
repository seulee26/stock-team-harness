# 오픈소스 심사

별이 많다고 넣지 않는다. 같은 다섯 항목으로 채점하고, 통과해도 실행해 본 뒤에만 넣는다.

## 지금까지의 평가 보기

```sh
python3 harness/connectors.py catalog
```

프로젝트마다 점수, 판정, 무엇을 어디에 반영했는지가 나온다. 판정은 네 가지다.

| 판정 | 뜻 |
| --- | --- |
| 연결 | 하네스 명령으로 직접 호출한다 |
| 접목 | 코드를 가져오지 않고 계산법의 일부를 하네스 기능으로 직접 구현했다. 원본 도구 전체를 넣은 것이 아니다 |
| 참고 | 설계나 경고 문구에만 반영했다 |
| 제외 | 목적이나 안전 기준에 맞지 않아 넣지 않았다 |

사용자에게 설명할 때 "접목"을 "탑재"나 "통합"으로 부풀리지 않는다. 성능을 비교 측정하지 않았으므로 "최고 성능"이나 "검증된 엔진" 같은 표현을 쓰지 않는다.

## 새 도구 평가하기

1. `oss-evaluator` 역할에 저장소 주소를 넘긴다. 저장소를 직접 확인할 수 없으면 사용자가 말한 내용으로 채점하고 그 값에 [확인 필요]를 붙인다. "실거래 가능"이라고만 들었으면 주문 기능을 떼어 쓸 수 있는지 모르는 것이므로 `separable`과 `core` 두 경우를 모두 보여 준다. 역할은 저장소에서 직접 확인한다: 라이선스 파일 원문, 마지막 갱신일, 주문 기능이 있는지와 분리해 쓸 수 있는지, 필요한 데이터와 키, 다루는 자산.
2. 채점한다.

```sh
python3 harness/connectors.py evaluate owner/repo --license MIT --live-orders none --months-since-update 2 --fit 2 --offline 2
```

| 항목 | 2점 | 1점 | 0점 |
| --- | --- | --- | --- |
| 라이선스 | MIT, Apache-2.0, BSD | LGPL, MPL | GPL, AGPL, 재판매 제한, 표기 없음(`none`) |
| 주문 위험 | 주문 기능 없음 | 있지만 분리 가능 | 실거래가 중심 |
| 유지보수 | 6개월 안에 갱신 | 2년 안 | 그보다 오래됨 |
| 적합성 | 미국·국내 주식과 선물 리서치에 맞음 | 일부만 | 대상이 다름 |
| 검증 가능성 | 키 없이 내 PC에서 확인 | 네트워크나 무료 키 | 유료 데이터·별도 장비 |

3. 합계 8점 이상이고 라이선스, 주문 위험, 유지보수가 각각 1점 이상이면 후보다. 후보라도 아래를 거친 뒤에만 넣는다.
   - 별도 가상 환경에 설치해 실제로 실행한다. 하네스 폴더에 직접 설치하지 않는다.
   - 무엇이 더 나아지는지 한 문장으로 적는다. 이미 있는 기능과 겹치면 넣지 않는다.
   - 넣는 방식을 정한다: 선택 설치하는 패키지를 명령으로 호출(연결)하거나, 필요한 계산만 직접 구현(접목)한다. 원본 코드를 복사해 넣지 않는다.
   - 테스트를 추가하고 `stock-harness-vibe-coding` 스킬의 절차로 변경한다.
4. 결과를 사용자에게 표로 보여 준다: 점수, 판정, 이유, 넣는다면 무엇을 어디에.

Codex에서는 `oss_evaluator` 역할을 쓴다.

## 지킬 것

- GPL, AGPL, 재판매 제한 라이선스, 라이선스 표기가 없는 코드는 가져오거나 함께 배포하지 않는다.
- 실거래가 중심인 도구는 넣지 않는다. 증권사나 거래소의 주문용 키를 연결하지 않는다.
- 키와 계좌 정보를 평가 대상 도구에 넘기지 않는다.
- 실행해 확인하지 않은 것은 참고로 둔다.
