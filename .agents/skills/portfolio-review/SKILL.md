# 포트폴리오 점검

종목 하나가 아니라 전체를 본다. 이 리포트에는 개인 보유 내역이 들어가므로 사용자 화면에만 보여 주고 공유용 리포트나 외부 연결로 보내지 않는다.

## 시작 전에 형식 확인

조사를 시작하기 전에 사용자에게 아래를 한 번에 묻는다. 선택지를 고르게 하는 질문 도구가 있으면 그것을 쓰고, 없으면 번호를 붙여 짧게 묻는다. 답을 받은 뒤에 조사를 시작한다.

1. 보유 내역을 받는 방법: 직접 알려 주기, 토스증권에서 조회하기
2. 깊이: 한 장 요약, 표준, 심층 (기본값: 표준)
3. 받는 형식: 채팅 답변, HTML 파일, HTML과 PDF. 파일을 Gmail로도 받을지 (기본값: 채팅 답변 (내 PC에서만))
4. 읽는 사람: 주식이 처음인 사람, 경험이 있는 사람 (기본값: 처음인 사람)

- 사용자가 요청에서 이미 밝힌 항목은 다시 묻지 않는다. 네 가지가 모두 정해져 있으면 묻지 않고 진행한다.
- 질문은 한 번만 한다. 사용자가 "알아서 해 줘"라고 하거나 답하지 않은 항목은 기본값을 쓰고, 어떤 기본값을 썼는지 결과 첫머리에 한 줄로 적는다.
- 메일로 받기를 고르면 리포트를 만든 뒤 `report-email` 스킬로 받는 사람과 내용을 확인받고 보낸다.
- 고른 깊이에 맞춰 조사 범위와 부르는 역할 수를 줄이거나 늘린다. 한 장 요약에 심층 조사를 붙이지 않는다.

## 순서

1. 보유 내역을 받는다. 사용자가 직접 알려 주거나, 토스증권이 연결돼 있으면 사용자가 요청했을 때 `python3 harness/stock_harness.py portfolio`로 조회한다. 조회 절차는 `stock-toss-readonly` 스킬을 따른다.
2. 전문 역할에 넘길 때는 종목 기호와 비중만 넘긴다. 계좌번호, 수량, 금액, 잔액은 넘기지 않는다.
3. 구성을 계산한다: 종목별 비중, 국가·통화별, 업종별, 상위 세 종목 합계.
4. `risk-officer`에 한도 점검을 맡긴다. 한도는 사용자가 정한 값을 쓰고, 없으면 기본값을 [가정]으로 표시한다. 같이 움직이는 종목은 하나의 위험으로 묶는다.
5. 비중이 큰 종목부터 `thesis-tracker`로 논지가 유효한지 본다. 기록된 논지가 없으면 없다고 알린다.
6. `python3 harness/desk.py event-list --days 30`으로 보유 종목과 관련된 일정을 확인한다.
7. `performance` 역할에 기록된 의견의 정산을 맡긴다.
8. 금리·환율 영향이 큰 구성이면 `macro`에 배경을 묻는다. 원화 투자자의 미국 주식은 환율 변동이 수익에 더해진다는 점을 적는다.

## 형식

1. 기준 시각과 한 줄 진단
2. 구성 표: 종목, 비중, 시장, 업종
3. 쏠림: 종목, 업종, 통화
4. 위험 점검: 걸린 한도와 줄여야 할 크기
5. 종목별 논지 상태
6. 앞으로 30일의 관련 일정
7. 점검할 것 세 가지

비중 조정은 "검토할 것"으로 쓰고 지시하지 않는다. 매도 비용이 궁금하면 `stock-sale-fee` 역할에 맡긴다. 주문은 사용자가 증권사에서 직접 한다.

## 발행 전 점검

1. `editor` 역할에 초안을 보내 쉬운 말, 구조, 숫자와 출처의 일치를 점검받는다.
2. `compliance` 역할에 표현, 고지, 개인정보, 출처를 점검받는다.
3. 파일로 저장할 때는 사용자가 지정한 내 PC 폴더에만 저장하고 공유 폴더나 외부 저장소에 올리지 않는다.

전문 역할을 쓸 수 없는 환경에서는 현재 세션이 같은 항목을 직접 확인하고 독립 검토를 거치지 않았다고 밝힌다. 리포트는 조사 자료이며 투자 조언이나 권유가 아니라고 적는다. Codex에서는 역할 이름이 `news_desk`, `market_sentiment`, `technical_analyst`, `sector_analyst`, `market_strategist`, `idea_screener`, `report_editor`, `compliance_officer`, `performance_analyst`다.
