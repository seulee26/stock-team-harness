# 대담 방송

앵커가 시청자가 궁금해할 질문을 던지고 전문가가 리포트의 내용으로 답한다. 혼자 읽는 해설보다 듣기 편하지만, 내용은 같은 리포트에서만 가져온다. 만들기 전의 선택지 안내와 도구 준비는 `report-broadcast` 스킬을 따른다.

## 대본 쓰기

형식은 `python3 harness/broadcast.py template --format interview`로 본다. 앵커 단독 대본과 다른 점은 세 가지다.

- 맨 위에 `"format": "interview"`와 `speakers`를 둔다. 출연자마다 `name`(화면 이름표), `voice`(오픈소스 TTS 목소리), 선택으로 `voice_id`(Typecast나 ElevenLabs 목소리 ID)와 `image`(진행자 그림)를 적는다.
- 장면에 `narration` 대신 `dialogue`를 쓴다. 한 마디마다 `speaker`와 `text`를 적는다. 한 장면에 1~8마디, 한 마디는 600자까지다.
- 화면 내용(제목, 표, 막대, 카드)은 앵커 단독 대본과 같게 쓸 수 있다.

`broadcast-writer` 역할(Codex는 `broadcast_writer`)에 리포트를 넘기면서 대담 형식이라고 알린다. 대본은 이렇게 쓴다.

- 앵커는 질문하고 정리한다. 시청자가 물을 만한 것, 의심할 만한 것을 대신 묻는다("이만큼 내렸으면 싼 것 아닙니까"). 숫자와 판단은 전문가가 말한다.
- 전문가의 답은 리포트에 있는 내용만 쓴다. 리포트에 없는 전망, 목표가, 매수·매도 권유를 대담이라는 이유로 덧붙이지 않는다.
- 한 마디는 두세 문장으로 짧게 주고받는다. 한 사람이 길게 말하면 둘로 나눈다.
- 불리한 내용도 앵커가 묻게 한다. 탈락한 종목, 위험, 확인하지 못한 수치를 빼지 않는다.
- 첫 장면에서 결론을 말하고, 마지막 장면에서 앵커가 정보 제공용 대담이며 투자 권유가 아니라는 점과 두 진행자의 목소리가 인공지능으로 만든 것이라는 점을 말로 읽는다.

## 출연자

- 이름표는 "AI 앵커", "AI 애널리스트"처럼 인공지능 진행자임이 드러나게 쓴다. 실제 앵커나 애널리스트의 이름, 증권사 이름을 쓰지 않는다.
- 목소리는 두 사람이 구별되게 고른다. 오픈소스 TTS는 `F1`과 `M2`처럼 다르게, Typecast나 ElevenLabs는 출연자마다 `voice_id`를 적는다. `voice_id`가 없는 출연자는 `--voice-id`나 환경 변수의 기본 목소리를 쓴다.
- 그림을 넣으면 말하는 사람이 밝게 표시된다. 그림이 없으면 이름 첫 글자가 나온다. 실제 인물 사진은 본인 동의 없이 쓰지 않는다.

## 만들기

```sh
python3 harness/broadcast.py check 대담.script.json
python3 harness/broadcast.py build 대담.script.json 대담.mp4
python3 harness/broadcast.py build 대담.script.json 대담.mp4 --tts typecast --speed 1.08 --music broadcast/music/곡.wav
```

`check`가 장면 수와 대사 수(`turns`)를 알려 준다. 자막에는 말하는 사람의 이름이 붙는다. `broadcast-director` 역할이 대본을 리포트와 대조하는 절차는 앵커 단독과 같다. 유료 음성 서비스는 마디마다 호출하므로 대사 글자 수만큼 요금이 든다고 알린다.

## 지킬 것

- 대담은 연출이다. 실제 인터뷰나 실제 전문가의 발언처럼 보이게 만들지 않는다.
- 숫자, 기준일, 판정은 리포트와 같아야 한다.
- 전문 역할을 쓸 수 없는 환경에서는 현재 세션이 대본 작성과 점검을 직접 하고 독립 검토를 거치지 않았다고 밝힌다.
